# 대화 한 권 · ChatGPT 대화 → PDF

ChatGPT 데이터 내보내기 **전체 ZIP**을 브라우저에서 열고, 제목으로 검색한 대화 하나를 PDF로 저장하는 한국어 정적 웹앱입니다. PDF 생성에는 브라우저 인쇄를 사용하므로 텍스트를 검색·복사할 수 있습니다. 전체 문서를 이미지로 캡처하지 않습니다.

서버, API 키, 계정 연결이 필요하지 않습니다. ZIP을 업로드하지 않으며 CDN, 외부 글꼴, 분석 도구도 사용하지 않습니다. 라이브러리와 수식 글꼴은 빌드 결과에 포함됩니다. 사용자가 외부 링크를 직접 누르면 해당 사이트로 이동합니다.

## 로컬 실행

Node.js **22.12 이상**과 npm을 설치합니다 (Node 24에서도 검증).

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 엽니다. `index.html`을 파일 탐색기에서 직접 여는 `file://` 방식은 지원하지 않습니다.

배포 빌드와 확인:

```sh
npm run build
npm run preview
```

`dist/`가 완성된 정적 사이트입니다. 빌드 이후에는 Node.js가 필요하지 않습니다. 라이브러리 버전은 `package.json`에 고정하고 전이 의존성은 `package-lock.json`으로 고정했습니다.

## GitHub Pages 배포

1. 이 프로젝트 전체를 저장소 `main` 브랜치에 올립니다. `node_modules/`, 개인 내보내기 ZIP, `test-results/`는 올리지 않습니다.
2. GitHub 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
3. `main`에 push하거나 Actions의 **Deploy GitHub Pages → Run workflow**를 실행합니다.
4. 워크플로가 테스트·빌드한 뒤 `dist/`를 Pages에 배포합니다. 완료된 배포 주소는 Actions 또는 Settings → Pages에서 확인합니다.

`.github/workflows/pages.yml`이 포함되어 있습니다. 저장소 설정에서 Actions와 Pages 사용 권한이 허용되어야 합니다. `vite.config.js`의 `base: './'`로 `/GPTchatconvert/` 같은 저장소 하위 경로와 사용자 사이트, 커스텀 도메인을 지원합니다. 개발 서버 주소나 소스 `index.html`을 Pages에 그대로 올리는 방식이 아니라 **빌드 결과**를 배포해야 합니다.

이 작업에서는 원격 push나 실제 Pages 배포를 수행하지 않았습니다.

## 사용법

1. ChatGPT의 설정 → 데이터 제어 → 데이터 내보내기로 받은 원본 ZIP을 선택합니다. iOS에서는 파일 앱에 ZIP을 저장한 뒤 파일 선택기에서 고릅니다. 압축을 미리 풀 필요는 없습니다.
2. 대화 목록에서 제목을 검색하고 대화 하나를 누릅니다. 많은 대화는 100개씩 표시하며 **더 보기**로 늘릴 수 있습니다.
3. 여러 분기가 있으면 경로 선택기를 확인합니다. `current_node`가 유효하면 그 지점까지의 경로를 기본으로 표시합니다. 현재 경로가 불명확하면 직접 선택해야 합니다.
4. 누락 이미지나 지원하지 않는 요소의 안내와 원문을 포함해 미리보기를 확인합니다. 글꼴·수식·이미지가 준비된 뒤에만 PDF 버튼이 활성화됩니다.
5. **PDF로 저장**을 누릅니다.
   - Windows Chrome/Edge: 인쇄 대상에서 **PDF로 저장** 또는 Microsoft Print to PDF를 선택합니다.
   - iPhone/iPad Safari: 인쇄 미리보기에서 공유 버튼을 사용하거나 미리보기를 두 손가락으로 확대하고, 공유 → **파일에 저장**을 선택합니다. OS 버전에 따라 버튼 위치와 순서가 다릅니다.
   - 문서 권장 설정: A4, 세로, 기본 배율 100%. 브라우저 머리글/바닥글은 필요하면 끕니다. 배경 그래픽은 선택 사항입니다.

화면의 목록·검색·버튼은 인쇄되지 않습니다. 선택한 경로의 제목·발화자·메시지만 출력됩니다. 원문 보존을 위해 지원하지 않는 요소의 원문 데이터도 인쇄합니다. 원문 상세를 화면에서 접었더라도 인쇄할 때는 자동으로 펼칩니다. 인쇄 창을 취소해도 미리보기는 유지됩니다.

새 ZIP을 열거나 새로고침하면 이전 대화를 비웁니다. 브라우저 저장소에 대화를 보관하지 않습니다. 읽기가 끝난 뒤 앱이 추가로 파일을 외부에서 가져오지 않습니다. 다만 오프라인 설치용 PWA는 아니므로 첫 페이지 접속에는 네트워크가 필요합니다.

## 지원하는 내보내기 구조와 가정

**실제 사용자 내보내기 ZIP 샘플은 제공되지 않았습니다.** 파서는 알려진 ChatGPT 내보내기 구조인 `conversations.json`의 `mapping` / `current_node` 모델에 맞춰 구현하고 합성 ZIP으로 검증했습니다. OpenAI의 모든 과거·미래 형식을 지원한다고 보장하지 않습니다. 내보내기 ZIP의 다른 개인 정보 파일은 읽지 않습니다.

ZIP 루트 또는 하위 폴더에 `conversations.json`이 정확히 하나 있어야 합니다 (`__MACOSX/` 보조 파일 제외). JSON 최상위는 대화 배열 또는 `{ "conversations": [...] }` 래퍼를 지원합니다. 각 대화에는 객체형 `mapping`이 필요합니다.

```json
[
  {
    "title": "예시 구조 · 실제 사용자 데이터 아님",
    "current_node": "answer",
    "mapping": {
      "root": { "parent": null, "message": null },
      "question": {
        "parent": "root",
        "message": {
          "author": { "role": "user" },
          "content": { "content_type": "text", "parts": ["질문"] }
        }
      },
      "answer": {
        "parent": "question",
        "message": {
          "author": { "role": "assistant" },
          "content": { "content_type": "text", "parts": ["답변"] }
        }
      }
    }
  }
]
```

- 순서는 타임스탬프가 아닌 **선택한 노드에서 `parent`로 연결된 조상 순서**로 복원합니다. 수정 전 질문·재생성 답변을 형제 분기로 합치지 않습니다. `children`과 타임스탬프를 추측에 사용하지 않습니다.
- `current_node`가 없거나 무효이면 `parent` 관계로 종단 노드를 찾습니다. 종단이 하나면 그 경로를 사용하고, 여러 개면 마지막 메시지 미리보기와 함께 선택지를 제공합니다. `current_node`가 중간 노드라면 그 노드까지만 표시합니다.
- `message: null`인 구조 노드는 건너뛰며 실제 메시지의 사용자·AI·시스템·도구 발화는 모두 표시합니다. 선택한 경로의 부모 누락이나 순환은 오류로 처리하고 인쇄를 막습니다.
- 알 수 없는 최상위 구조, `mapping` 없는 대화, 잘못된 JSON, 손상된 ZIP, `conversations.json` 누락/중복은 명시적 오류를 표시합니다. 일부 대화를 조용히 버려 성공한 것처럼 표시하지 않습니다.
- `chat.html` 단독 내보내기, 공유 링크, API 응답의 `messages` 배열은 현재 지원하지 않습니다.

## 서식·이미지·안전성

| 요소                                          | 처리 방식                                                                                                                              |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 한국어·제목·문단·목록·강조·링크·인용문·표     | GFM Markdown 렌더링, 기기 시스템 한국어 글꼴 사용                                                                                      |
| 코드                                          | 들여쓰기·줄바꿈·탭 유지, 긴 줄은 출력 너비에 맞게 시각적으로 줄바꿈. Python·JavaScript·JSON·Bash 구문 색상, 나머지는 원문 코드         |
| 수식                                          | `$…$`, `$$…$$`, `\(…\)`, `\[…\]`를 KaTeX로 표시. 코드 내부는 변환하지 않음. 실패한 수식은 오류 안내와 TeX 원문을 표시                  |
| 이미지                                        | Markdown 이미지 및 `image_asset_pointer.asset_pointer`를 ZIP 항목에 연결. PNG·JPEG·GIF·WebP의 실제 시그니처를 확인하고 Blob URL로 표시 |
| 없는 이미지·외부 URL 이미지                   | 원격 다운로드 없이 누락 사유·원래 참조 주소를 표시                                                                                     |
| 음성·동영상·Canvas 등 알 수 없는 content/part | 지원하지 않는 요소임을 표시하고 원본 JSON을 그대로 표시                                                                                |
| 첨부·출처 정보                                | `attachments`, `citations`, `content_references`, `search_result_groups`는 원문 JSON을 추가 표시                                       |
| HTML·스크립트                                 | 실행하지 않고 HTML 원문을 코드 블록으로 표시. HTML 안의 이미지도 실행하지 않음                                                         |

이미지 경로는 ZIP 내 정확한 경로, 고유한 경로 접미사 또는 `file-…` / `file_…` ID의 파일명 접두사를 사용합니다. `file-service://`, `sediment://`, `attachment://`와 `sandbox:/mnt/data/` 참조를 처리합니다. 일치 후보가 여러 개면 임의로 고르지 않습니다. 이미지가 ZIP에 있어도 참조 이름과 매칭되지 않거나 인코딩을 지원하지 않으면 원래 참조와 실패 사유를 표시합니다. SVG·HEIC·PDF 첨부의 이미지 변환은 하지 않습니다.

Markdown 결과는 DOMPurify로 정화하고, 수식의 `trust`를 끄며, 원문 HTML을 먼저 이스케이프합니다. 사용자 콘텐츠로 이벤트 핸들러·스크립트·iframe·스타일·외부 이미지가 실행되지 않게 처리합니다. CSP도 외부 스크립트·이미지·글꼴·연결을 제한합니다. 일반 HTTP(S)·메일 링크는 사용자가 눌렀을 때만 열립니다. 지원하지 않는 링크 주소는 원문 주소와 안내를 남깁니다.

## 인쇄와 알려진 한계

- 인쇄 전 실제 표시된 문서의 이미지 디코딩·수식 렌더링·`document.fonts.ready`를 기다립니다. 이미지 디코딩 실패/시간 초과는 안내로 대체한 뒤 인쇄할 수 있게 합니다.
- A4 인쇄 스타일에 표 열 너비 고정, 긴 단어·코드 줄바꿈, 머리행 반복, 이미지 크기 제한을 적용합니다. 긴 메시지·표·코드 블록은 페이지 사이에서 나눌 수 있습니다. 긴 수식은 너비에 맞춰 글자 크기를 줄입니다.
- 긴 코드의 **원문 문자열**은 유지하지만 인쇄에서는 긴 줄이 시각적으로 접힙니다. 수식·PDF의 정확한 텍스트 추출 순서는 브라우저와 글꼴에 따라 다릅니다.
- 브라우저 인쇄 엔진마다 페이지 나눔과 여백 처리가 다릅니다. 수십 열의 표나 극단적으로 긴 수식은 작게 보일 수 있습니다. 모든 문서에서 동일한 페이지 배치를 보장하지 않습니다.
- JSON 압축 해제 크기 한도는 **256 MiB**, 이미지 하나는 **30 MiB**, 한 ZIP에서 읽은 이미지 캐시 합계는 **300 MiB**입니다. 전체 ZIP을 한꺼번에 풀지 않고 JSON과 선택된 대화의 이미지만 읽습니다. 여러 대화를 둘러보며 이미지 캐시가 한도에 도달하면 새로 ZIP을 열어 초기화할 수 있습니다.
- JSON 파싱은 브라우저 메인 스레드에서 수행합니다. 읽기 진행률과 분석 상태는 표시하지만 매우 큰 JSON의 파싱 중에는 화면 반응이 잠시 멈출 수 있습니다. iOS 메모리 한계는 기기마다 다르며 한도 이하 파일도 실패할 수 있습니다. 이 경우 메모리가 충분한 PC에서 시도하세요.
- 파일 선택은 Safari 16.4+ / 최신 Chrome·Edge·Firefox를 대상으로 구현했습니다. 모든 실제 기기의 동작을 검증한 것은 아닙니다.
- Markdown의 줄바꿈 규칙(GFM)을 따릅니다. 단일 개행은 문단 내부 공백으로 보일 수 있습니다. `$…$`는 수식으로 해석하므로 통화 표기는 `\$`로 이스케이프해야 할 수 있습니다. KaTeX가 지원하지 않는 LaTeX 매크로는 원문으로 남깁니다.
- 앱의 `npm run dev`는 개발용 서버입니다. ZIP 내용은 저장·전송하지 않지만, 개발 서버를 인터넷에 직접 공개하는 운영 방식은 사용하지 마세요. 배포에는 `dist/`와 GitHub Pages를 사용합니다.

## 테스트와 확인 범위

테스트 데이터는 `tests/fixtures.js`에서 생성하는 **합성 데이터**입니다. 실제 사용자 대화나 실제 OpenAI 내보내기 파일로 제시하지 않습니다.

```sh
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run test:production
```

E2E 테스트는 `pdftotext`도 필요합니다 (Ubuntu/Debian: `poppler-utils`). 기본 Playwright Chromium 대신 설치된 Chromium을 쓸 때는 `CHROMIUM_PATH` 환경 변수에 실행 경로를 지정합니다. `test:production`은 먼저 빌드한 `dist/`를 `/GPTchatconvert/` 경로에서 확인합니다.

이번 작업에서 실제로 확인한 항목:

- Linux Node.js 24.19, 시스템 Chromium 154 headless.
- 파서 단위 테스트 8개: 분기 분리·현재 노드·단일/복수 경로·손상 경로·알 수 없는 구조·미지원 콘텐츠·이미지 매칭.
- Chromium 데스크톱 1440×1000, 휴대폰 크기 390×844, 태블릿 크기 820×1180에서 파일 선택·검색·미리보기·경로 선택·오류 후 복구·인쇄 호출·글꼴 준비 대기.
- 한국어·수식 5개·표·들여쓴 코드·ZIP 이미지·누락 이미지·음성 미지원 원문·악성 HTML/외부 이미지 요청 방지.
- 합성 160개 메시지, 100행 표, 160줄 코드가 포함된 **43쪽 PDF**에서 모든 메시지와 마지막 표·코드 줄을 `pdftotext`로 검증. 서식 테스트 PDF는 3쪽이며 한국어 검색 가능한 텍스트와 마지막 내용 보존, UI·다른 분기 제외를 확인. 화면 미리보기와 PDF 첫 페이지도 시각적으로 확인.
- 프로덕션 빌드와 저장소 하위 경로에서 JS·CSS·수식 글꼴·ZIP 읽기 및 외부 요청 부재.

**확인하지 못한 항목:** 실제 Windows 브라우저의 OS 인쇄 대화상자, 실제 iPhone/iPad Safari와 파일 앱 공유 흐름, Firefox/WebKit 인쇄, 실제 사용자 내보내기 ZIP, 수백 MiB 이상의 메모리 부하. 휴대폰·태블릿 크기의 Chromium 테스트가 실제 iOS 검증을 대신하지는 않습니다. Pages 실배포도 수행하지 않았습니다.

테스트 출력은 `test-results/`에 생성되며 Git에서 제외됩니다. 개인정보 ZIP은 테스트 픽스처로 커밋하지 마세요.

## 파일 구성

```text
index.html                    한국어 화면
```
